# ナビゲーションのデザイン案

Issue #240。**全デザインの正本はPenpot**。アプリ本体は変更しない。

編集用ファイル: [burgerstack-navigation.penpot](../files/burgerstack-navigation.penpot)

[ローカルPenpotで開く](http://localhost:9001/#/workspace?project-id=001b6a38-fea0-8183-8008-b179064866fd&file-id=001b6a38-fea0-8183-8008-b21528f5e80f&page-id=001b6a38-fea0-8183-8008-b21528f5e810)

PC、スマホのホーム・探す・記録する・マイページ、フッター末尾、未ログイン、320pxの9ボード。文字・矩形・アイコンは編集可能。画像を1枚貼ったものではない。
既存の全体デザインを上書きせず、今回の検討を別ファイルとして管理する。採用後に全体デザインへ統合する。
HTMLは操作確認用の補助。Penpotで変更した場合は、書き出しファイル・プレビュー・補助HTMLを同じ変更に揃える。競合時はPenpotを正とする。

## 開き方

リポジトリのルートから `python3 -m http.server 5191 --bind 127.0.0.1 --directory design` を実行し、
`http://127.0.0.1:5191/navigation/` を開く。依存パッケージ不要。

- `prototype.html`: 画面幅に追従する案。下部ナビ、探す対象、紹介・プロフィールへ移動可能。
- `prototype.html?guest=1#record`: 未ログイン時の投稿入口。
- `prototype.html?guest=1#profile`: 未ログイン時のマイページ。
- 検索・認証・投稿は行わない。ダイアログで想定導線を説明する。
- 写真、店舗名、商品名、評価はサンプル。相互の実際の対応を示さない。

## 配置

PC（1024px以上）はロゴ／紹介／「次の一口を探す」／白地に枠線の食べた記録ボタン（ハンバーガー＋プラス）／プロフィール。「次の一口を探す」から、お店・バーガー・レビューを同じ画面のタブで切り替える。検索の入口を一か所にまとめ、探し方は遷移先で選べる。
スマホ・タブレット（1023px以下）は上部にロゴと「Burger Stackについて」、下部に「次の一口・記録する」を含む4項目を固定。「次の一口」は画面幅を考慮した短い表示で、読み上げ名は「次の一口を探す」。
320pxではロゴの文字だけ省略し、正式なサービスマークと紹介リンクを保つ。紹介リンクは省略しない。

| 下部ナビ | 行き先と選択状態 |
| --- | --- |
| ホーム | `/`。ランキング・新着の入口。トップで選択 |
| 次の一口 | `/discover`。表示ラベルは「次の一口」、読み上げラベルは「次の一口を探す」。お店・バーガー・レビューを同じ画面内タブで切り替え |
| 記録する | 店舗選択から投稿へ。店舗選択とフォームで選択 |
| マイページ | 本人の `/users/:id`。プロフィール編集・接続済みアプリ・サインアウトへ。本人画面と設定で選択 |

紹介・AI案内などの情報ページでは下部ナビを未選択。他人のプロフィールもマイページ選択にしない。
記録するは色で常時強調せず、他の項目と同じ見た目にそろえる。アイコンは白い中身と黒い輪郭のハンバーガーの右上に小さな「＋」を添え、選択状態は淡い背景・太字・ラベル下線で示す。
アイコンは24pxの線画、ラベルは11px、各項目は最低64px高。画面下のセーフエリアを足す。
ボタンの浮き上がりや中央の巨大な円は使わず、4項目のタップ領域を均等に保つ。

## 状態・動作の引き継ぎ

- 未ログインの記録・マイページはサインイン/登録へ。成功後は元の目的の画面へ戻す。実装時は既存認証フローに合わせる。
- 投稿途中に別タブへ移る場合は入力破棄の確認が必要。投稿完了後は本人のレビュー詳細へ。
- スマホで入力キーボードが表示された場合、固定ナビが入力・送信を隠さないよう実機確認する。必要ならキーボード表示中は下部ナビを隠す。
- 現在地は `aria-current` で伝える。表示していないPC/mobileナビは `display:none` で二重読み上げを避ける。
- 色だけに頼らず選択を示し、フォーカス輪郭と本文スキップリンクを用意。遷移時は本文にフォーカス。
- 末尾には下部ナビ80px＋safe-area分の余白を置き、フッターが最後まで見えるようにする。
- ネットワーク失敗・空状態・非公開ページでもナビは残す。業務上の権限判断はbackendを維持。

## フッター

ブランド＋短いメッセージ、Burger Stack（紹介・AIから使う）、サポート（FAQ・問い合わせ）、運営情報（規約・プライバシー）。最下段に言語とコピーライト。
FAQ・問い合わせ・規約・プライバシーは配置予約の静的テキスト。リンクを捏造していない。アプリ実装時は実在ページだけを表示し、未作成項目は非表示。
言語ボタンはプレビュー内では説明のみ。実装時は既存i18nへ接続。

## 維持するもの・対象範囲

サービスマークは `design/assets/logo/burgerstack-mark.svg`、評価は `design/redesign/rating-icons.js` をそのまま参照。記録ナビのアイコンは白いバーガーに「＋」を添えた形にし、サービスマークを流用しない。
写真は `design/refresh/assets/sample-burger.jpg`。本文のカードはナビを見比べるためのサンプルで、本文全体のリデザインを確定するものではない。
フォントはOSにあるNoto Sans JP/system sans。実装時は既存の同梱Noto Sans JPを使用する。

## Penpotの生成・更新

`captures/*.json` はブラウザの読み取り専用計測データ。`build_penpot.py --email <ローカルPenpotのメール> --password-file <非公開ファイル>` で新規ファイルへ取り込み、`../files/burgerstack-navigation.penpot` に書き出す。既存のファイルを更新するスクリプトではないため、Penpotで編集した後に再生成して上書きしない。
`boards.json` がボードIDの対応。`previews/*-penpot.png` はPenpot exporterの出力、`*-source.jpg` は操作確認用ブラウザ画像。

記録アイコンの＋には丸枠を付けない。PCの記録ボタンはホバー・キーボードフォーカスで背景が #fff1bb に変化する。Penpotの「PC / 記録ボタンのホバー」で比較できる。

＋はハンバーガー右上に重ねる。＋の周囲ではバーガーの輪郭線を途切れさせ、両者の線が接続しない余白を確保する。丸枠は付けない。
