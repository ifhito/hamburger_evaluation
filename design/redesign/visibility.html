実装メモ
  • ・この一覧は、いまの実装(backend-go の domain の規則と、frontend の出し分け)から起こした。規則は backend の domain だけが持つ(レビューを直せるのは投稿者だけで、管理者に例外はない・レビューを書けるかは、公開中なら誰でも、審査待ちは作った人と管理者だけ、却下は誰も書けない・ショップの見える範囲・プロフィールを直せるのは本人だけ)。
  • ・frontend は、can_edit・can_review・can_moderate・can_approve・can_reject を、返されたまま使う。値が false の部品は、出さない(押せない状態で見せない)。
  • ・API の項目ではなく、サインインの状態で決めるもの(「ショップを追加」・ヘッダー・サインイン画面など)は、根拠の欄にそう書いた。追加や変更の操作そのものは、どれも API がサインインを求める。
  • ・「案」と書いたもの(サインインしていない人への「サインインして、レビューを書く」)は、いまのアプリにない。
  • ・Google ログインの行の項目名は、実装(PR #124・#126)の実際の名前(login_providers・can_unlink・can_edit・return_to)で確かめた。判断は backend だけが持ち、frontend は、返された項目で出し分けるだけ(パスワードがあるか・解除してよいかを、frontend が判断しない)。
