実装メモ
  • ・この画面(/auth/google/complete?code=…)は、Google の手続きの結果の受け皿。backend が、成功も失敗も、60 秒だけ有効な 1 回限りのコードに入れて、この画面へ戻す。ここでは、コードを API と交換して結果を受け取るだけで、成功か失敗か・理由の判断は持たない。コードは 1 回しか使えないので、最初に 1 回だけ読み、URL からはすぐに消す(履歴に残さない)。ログインの証(JWT)は URL に載らない。
  • ・赤い枠の文言(An account with this email address already exists… など)は、API が返したものをそのまま出す(いまの API の文言は英語だけ。日本語にするのは API の多言語化の story)。見出し(「Google でサインインできませんでした」)と、太字の小見出し(「同じメールのアカウントがあります」など)だけが、画面側の言葉。小見出しは、API が返した結果の種類(409 の理由)ごとに、画面が付ける案で、API が種類を返さないなら、小見出しを付けずに、API の文言だけを出す案もある。
  • ・「リンクが使えなくなりました」(expired)は、リンクが無効なのか期限切れなのかを、API は区別しない(同じ文言。有効期間は 60 秒)。見出しも、区別しない言い方にしている。
  • ・元の画面へ戻れる: 「exists-oauth」の枠(「サインインすると、元の画面に戻ります」)は、backend が失敗の応答にも、確かめた戻り先(return_to)を含めたとき(#124 の修正中の項目)に、出す。戻り先があるかどうかだけで出し分け、戻り先が何の画面かの判断は持たない。サインインしたあと、その戻り先へ移す。
  • ・失敗のあとの操作は、案: 同じメールのアカウントがある・すでに連携済み → 「パスワードでサインインする」(1 つだけ)、失敗・期限切れ → 「Google でサインイン」(もう一度。ボタンの見た目は、ボタンの案に従う)と、「パスワードでサインインする」。いまの実装は、「サインイン画面へ戻る」のリンク 1 つだけ。
  • ・連携(プロフィールから始めた手続き。サインイン済み)の失敗は、「プロフィールに戻る」だけを出す。
  • ・読み込み中の絵は飾りなので、読み上げない。「サインインしています…」は、読み上げる(aria-live)。
