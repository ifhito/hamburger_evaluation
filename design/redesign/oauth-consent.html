実装メモ
  • ・「何のアプリに、何を許すか」を、いちばん目立たせる。アプリの名前(大きな文字)と、アプリ ID を、黒い太い枠の面に置き、その下に「許可すること」を並べる。アプリの名前は、アプリが自由に決められるので、HTML として解釈せず、文字として出す。戻り先のホスト(ここでは localhost:53412)は、利用者が、どのアプリ・どこへ、を見比べるための表示で、判断には使わない。
  • ・範囲の説明文(「ショップ・レビュー・プロフィールを読む」など)は、API が返したものをそのまま出す。frontend に、範囲の名前や説明を持たない。いまの API の説明文は日本語だけ(英語の画面で英語にするには、API が言語に合わせて返す必要がある)。「書き込み」の範囲を強調する(目立つ印を付ける)には、範囲ごとの印を API が返す必要がある(いまは、名前と説明だけ。frontend が名前を比べて決めると、規則の複製になる)。
  • ・「許可する」は、黄色の面のボタン、「許可しない」は白い面に枠のボタン。どちらも 44px 以上。送っている間は、両方押せなくする(二重に送らない)。「許可すること」の下の説明(プロフィールで解除できる)は、案(いまのアプリにはない)。
  • ・要求の検証・範囲の説明・「すでに許可済みの範囲に収まるか(尋ねなくてよいか)」の判断は、すべて backend。frontend は、結果の表示と、利用者の選択の送信だけ。エラーの文言(oauth authorization request is invalid など)は、API が返したものをそのまま出す。見出しと「アプリに戻って…」だけが、画面側の言葉。
  • ・なりすまし対策: 画面に見せている要求と、送る要求が、必ず同じになるようにする(URL の値が変わったら、いったん「確認中」に戻し、古い画面のボタンは押せない)。アプリへ戻せない不正な要求は、アプリに戻さず、この画面にエラーを出す。
  • ・サインインしていない人が来たときは、サインイン画面へ送り、サインインのあとで、この画面へ戻す(「サインイン(アプリの接続の途中)」の見本)。
