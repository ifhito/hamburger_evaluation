## 先に結論

個人開発のハンバーガーレビューアプリ(Go + React)を、できるだけ無料で動かしたい。そう思って調べ始めたら候補が多すぎたので、**DB・写真ストレージ・メール・API・フロントの 5 層で 4 つずつ、計 20 サービスに実際にデプロイして比べました**。

最終的にこうなりました。

| 層 | 採用 | 決め手 |
|---|---|---|
| API | **Cloud Run**(東京) | 写真処理・SMTP・常駐ワーカーが全部動いた唯一の候補でした |
| DB | **Neon** | 日本から一番近く、マイグレーションが無改変で通りました |
| 写真 | **Cloudflare R2** | 転送量が無料・無制限です |
| メール | **Resend** | 送信元の検証がちょうどよい厳しさでした |
| フロント | **Cloudflare Workers** | API への転送が速く、帯域が無制限です |

一番の学びは、**無料枠の落とし穴は料金表に書いていない**ということです。20 サービスすべてで、実際に使ってみるまで分からない制約に当たりました。

## 何をどう比べたか

**本物のアプリをそのまま置いて測りました。** ミニマムなサンプルだと、写真処理で使うメモリや SMTP のポートのような、実際に効いてくる制約が見えないからです。

アプリは Go 1.27(標準 `net/http` + sqlc + pgx)と React 19 の SPA です。DB は PostgreSQL で主キーは UUID、レビューの写真はサーバー側で長辺 1600px に縮小し、サインアップの確認メールを SMTP で送ります。

候補の条件は「無料で始められて、個人が一人で登録から運用までたどり着けること」にしました。営業への問い合わせが要るもの、自前でサーバーを運用するもの、IAM の設計が要るものは外しています。

計測は日本の自宅回線からで、数字は p50(中央値)です。順序は DB → 写真 → メール → API → フロントで、後ろの層は前の層で選んだものに向けて測りました。

候補は延べ 80 ほど見て、層ごとに 4 つに絞りました。選ばなかったサービスについても、運営・概要・無料枠・向いている人を記事末尾の「付録」にまとめています。前提が違えば、そちらのほうが合うこともあるはずです。絞り方は**「同じ軸を代表するものを 2 つ入れない」**です。各層の最初に、候補に挙がったもの全部と、なぜその 4 つにしたかを書いています。

## 1. データベース

### 候補に挙がったもの(19)

| 区分 | サービス |
|---|---|
| **選んだ 4 つ** | **Neon、Supabase、Render Postgres、Xata** |
| 技術的に使えない | Aurora DSQL(外部キー非対応)、Cloudflare D1(Workers 内専用)、MongoDB Atlas / DynamoDB(リレーショナルでない) |
| 別の道具に乗り換えることになる | PlanetScale、TiDB Serverless(MySQL)、Turso、SQLite + Litestream |
| 要件に対して過剰 | CockroachDB、YugabyteDB(分散 SQL) |
| 他と差がつかない | Aiven、Prisma Postgres、Nile |
| 無料で始められない | Fly Postgres |
| 個人には運用が重い | Oracle Cloud の VM に自前構築 |
| 登録できなかった | Koyeb Postgres |

### なぜこの 4 つか

このアプリは pgx + sqlc で、UUID 主キー・外部キー 6 本・`FOR UPDATE SKIP LOCKED` を使っています。なので「Postgres のワイヤプロトコルで、これらがそのまま動くこと」が最低条件になります。ここで MySQL 系と SQLite 系と NoSQL が落ちました。

残った Postgres 勢から、**違う軸を代表する 4 つ**を選んでいます。

- **Neon** は「休む DB」の代表です。使った時間で課金する方式が、個人アプリで本当に無料で収まるのかを見たかった
- **Supabase** は 4 社で唯一、東京リージョンがあります。「1 週間触らないと止まる」という変わった挙動も測っておきたかった
- **Render Postgres** は「API と同じ事業者に置く」構成を試すために入れました。API の当初の第一候補が Render だったからです
- **Xata** はニッチ枠です。日本語の情報がほぼなく、測ること自体に価値があると思いました

### 4 社の顔ぶれ

**Neon**(Databricks 傘下・米)は、サーバーレスの Postgres です。無料で使えるのは保存 0.5GB、コンピュート 100 CU 時間/月までで、カードは要りません。超えると従量課金で $0.106/CU 時間、保存 $0.35/GB 月になり、月額の最低額はありません。5 分触らないと自動で休止し(無料枠では無効化できません)、DB を Git のようにブランチできるのが特徴です。

**Supabase**(シンガポール)は、Postgres を中心に認証やストレージまで 1 つのプロジェクトで提供する「Firebase 代替」です。無料枠は DB 500MB、プロジェクト 2 つまでで、カードは要りません。ただし **1 週間触らないと一時停止します**。超えると Pro $25/月(DB 8GB 込み)です。東京リージョンがあります。

**Render Postgres**(米)は、アプリ基盤 Render のマネージド Postgres です。無料枠は 1GB、256MB RAM ですが、**作成から 30 日で失効します**。有料は $6/月(256MB)からです。同じ Render の Web サービスと私設ネットワークでつながるので、常用するなら有料前提の選択肢になります。

**Xata**(米)は、ブランチ機能を中核にした Postgres です。現在の料金ページには常設の無料枠がなく、14 日の試用だけになっていました(検証した時点では無料で使えました)。有料はコンピュート $0.012/時から、保存 $0.28/GB 月です。差分だけ課金される Copy-on-Write のブランチと、ゼロダウンタイムのスキーマ変更が売りです。

### 実測

日本から pgx で直接叩いて、各 200 回測りました。

| 候補 | リージョン | 往復(SELECT 1) | 書き込みトランザクション |
|---|---|---|---|
| **Neon** | シンガポール | **86ms** | **348ms** |
| Supabase | ムンバイ | 131ms | 527ms |
| Render | オレゴン | 146ms | 588ms |
| Xata | 米国東部 | 177ms | 714ms |

**差は距離だけでした。** 4 社ともマイグレーション 12 本が無改変で通り、互換性では差がつきません。

意外だったのは、主キーでの 1 件取得も、3 テーブルを結合した 20 件も、`SELECT 1` と区別がつかなかったことです。この規模だと DB の処理時間はネットワークの往復に完全に埋もれてしまいます。

書き込みだけが 4 倍遅いのは、BEGIN から COMMIT まで 4 往復しているからです。4 社とも倍率がぴったり 4.02〜4.04 で揃いました。時間を決めているのは DB の性能ではなく往復回数なので、CTE で 1 文にまとめれば 1 往復にできます。

### ハマったこと

- **Supabase** は Direct connection が IPv6 専用で、Docker から名前解決できませんでした。psql では繋がるので「マイグレーションが失敗してテーブルがない」という分かりにくい形で出ます。Session pooler を使えば通ります
- **Neon** は pooler 経由だとマイグレーションが `unnamed prepared statement does not exist` で落ちることがありました。直結の URL を使えば大丈夫です
- Render と Xata ではハマりませんでした。なお Supabase は新規なら東京で作れるので、そうすれば順位は変わるはずです

## 2. 写真ストレージ

### 候補に挙がったもの(19)

| 区分 | サービス |
|---|---|
| **選んだ 4 つ** | **Cloudflare R2、Tigris、Supabase Storage、Backblaze B2** |
| S3 互換でない(コードを書き足す) | Vercel Blob、Cloudflare Images、Bunny Storage |
| 用途が違う(画像変換に特化) | ImageKit、Cloudinary、Uploadcare / Uploadthing |
| 無料枠がない、または期限付き | AWS S3、Google Cloud Storage、Azure Blob、Wasabi、DigitalOcean Spaces、Hetzner |
| 運用が重い、条件が読めない | MinIO(セルフホスト)、Storj、Render Disk |

### なぜこの 4 つか

アプリのアダプタが使うのは S3 互換の `PutObject` と `DeleteObject` だけで、公開 URL からそのまま配信します。なので「S3 互換で、公開配信できること」が条件です。このアプリは保存時に縮小まで済ませているので、変換特化のサービスには出番がありませんでした。

写真は 1 回書いて何度も読まれるので、**転送量の課金を一番重く見ています**。

- **R2** は費用の面で第一候補でした。転送量が無料という一点が大きい
- **Supabase Storage** は、DB を Supabase にするなら一体で使えるかを見るために入れました
- **Tigris** は、アクセス元に寄せる分散型が速さにどう出るかを見たくて入れました
- **B2** は R2 登場前の定番で、4 社で唯一カードが不要です

### 4 社の顔ぶれ

**Cloudflare R2**(米・上場)は、S3 互換のオブジェクトストレージです。無料枠は保存 10GB、書き 100 万回/月、読み 1,000 万回/月で、カード登録は要ります。超えると保存 $0.015/GB 月ですが、**転送はいくら読まれても $0** です。これだけで選ぶ理由になります。

**Tigris**(米)は、全世界に分散する S3 互換ストレージです。無料枠は保存 5GB、書き 1 万回/月、読み 10 万回/月で、転送は無料です。超えると保存 $0.02/GB 月になります。データがアクセス元に追従して分散し、リージョン別の課金がありません。

**Supabase Storage**(シンガポール)は、Supabase プロジェクトに付属するファイル保存です。無料枠は 1GB、転送 5GB/月で、DB と同じく 1 週間触らないと休止します。超えると Pro $25/月(100GB 込み)、転送 $0.09/GB です。DB・認証と同じ権限(RLS)で扱えるのが強みですが、単価は R2 や Tigris より高めです。

**Backblaze B2**(米・上場)は、S3 互換の老舗ストレージです。最初の 10GB が常時無料で、転送は保存量の 3 倍/月まで無料、**カードも要りません**。超えると保存 $6.95/TB 月(約 $0.007/GB)と最安級で、最短保存期間などの縛りもありません。

### 実測

300KB の JPEG を各 50 回測りました。

| 候補 | PUT | GET | GET のばらつき |
|---|---|---|---|
| Tigris | **89ms** | **26ms** | 小 |
| Supabase Storage | 433ms | 39ms | **大**(最大 780ms) |
| **Cloudflare R2** | 160ms | 81ms | 中 |
| Backblaze B2 | 233ms | 281ms | **最小**(8.5ms) |

**速さでは Tigris が全項目で最速でした。** GET 26ms は R2 の 3 分の 1 です。それでも R2 を選んだのは、転送量の課金が長期的に効いてくるからです。

Supabase は中央値こそ速いのに、2 割ほどの閲覧で目に見えて待たされます。B2 は遅いけれど最も安定していました。**平均だけ見ると判断を誤ります。**

Region を `auto` に固定しているコードも、4 社ともそのまま通りました。エンドポイントと鍵を差し替えるだけで動きます。

### ハマったこと

- **B2** はマスターキーが S3 API で使えません。画面上部に大きく出ているアカウント ID を入れてしまい `Malformed Access Key Id` になりました。App Keys から作り直すと通ります
- **R2** はバケット名の指定違いで `NoSuchBucket` になりました。公開 URL の `*.r2.dev` は開発用なので、本番は独自ドメインが要ります
- Tigris と Supabase ではハマりませんでした

## 3. メール送信

### 候補に挙がったもの(15)

| 区分 | サービス |
|---|---|
| **選んだ 4 つ** | **Resend、Mailjet、Brevo、MailerSend** |
| 登録の障壁で失格 | SMTP2GO(フリーメール不可)、SendGrid(審査で止まる報告が多い)、Amazon SES(サンドボックス解除の申請が要る) |
| 規約上、本番で使えない | Gmail SMTP、Outlook SMTP |
| 無料枠が小さい、または試用のみ | Mailgun(100 通/日)、Postmark(100 通/月)、ZeptoMail(初回 1 万通のみ) |
| 立地や条件が合わない | Scaleway(EU のみ)、Elastic Email、Loops / Plunk |

### なぜこの 4 つか

実装は SMTP だけで、送るのは 1 日数通です。なので「SMTP で送れて、個人が登録できること」が条件で、**無料枠の通数はどこでも余るので見ませんでした**。

- **Mailjet** は制約の少なさで当初の第一候補でした。ドメインなしで任意の宛先に送れます
- **Resend** は、API キー 1 つで送れる最短経路がどこまで短いかを見るために入れました
- **MailerSend** は配信事業者の出自です。Resend と同じ「ドメイン前提」の方式が、別の会社でどう違うかを見たかった
- **Brevo** は繰り上げです。一度は外したのですが、代わりに入れた SMTP2GO がフリーメールで登録できず、戻しました

### 4 社の顔ぶれ

**Resend**(米)は、開発者向けのトランザクションメール API です。無料枠は 3,000 通/月、100 通/日、ドメイン 3 つで、送信にはドメインの検証が必須です。超えると Pro $20/月(5 万通)になります。無料でも独自ドメインを複数登録できます。

**Mailjet**(Sinch 傘下・スウェーデン)は、マーケティングとトランザクション両方をこなす配信基盤です。無料枠は 6,000 通/月、200 通/日と 4 社で最大ですが、Mailjet のロゴが付きます。超えると Starter $9/月(8,000 通)です。送信元の検証が 4 社で最も緩いのが特徴です。

**Brevo**(旧 Sendinblue・仏)は、マーケティング中心の配信基盤に SMTP リレーが付いたものです。無料枠は 300 通/日でした(検証時の記録で、公式ページは今回取得できませんでした)。超過後の料金は未確認です。送信元 IP の登録と、登録時に企業名が要ります。

**MailerSend**(米・MailerLite と同じチーム)は、トランザクションメールの API と SMTP です。無料枠は 500 通/月、ドメイン 1 つと小さめですが、有料は Hobby $5.60/月(5,000 通)と最安です。

### 実測

計測は 2 段階になりました。**独自ドメインを持たない状態と、取得して認証したあと**です。

| 候補 | ドメインなし | ドメイン認証後 | 解決に要った作業 |
|---|---|---|---|
| Mailjet | **送れた** | 送れた(4 秒) | なし |
| **Resend** | 自分宛てにしか送れない | 送れた(4 秒) | DKIM の登録 |
| MailerSend | `450 domain must be verified` | 送れた(6 秒) | SPF と DKIM の登録 |
| Brevo | `525 Unauthorized IP` | 送れた(2 秒) | **送信元 IP の登録**(ドメインでは解決しない) |

ドメインなしで送れたのは Mailjet だけでした。ドメインを認証したら 4 社とも送れて、迷惑メールにも入りませんでした。

最初は関門のない Mailjet を選びました。でも **Mailjet は認証していないドメインのアドレスからでも送れてしまいます**。これは利点ではなく弱点だと考え直して、Resend に変えました。鍵が漏れたら任意の差出人で送られてしまいますし、他社なら弾かれる設定ミスに気づけないからです。

### ハマったこと

- **Brevo** はドメイン認証を済ませても `525 Unauthorized IP` が残りました。送信元 IP を登録して初めて通ります。IP が固定されない Cloud Run とは相性が悪いです
- **MailerSend** は設定不備に 450(一時的エラー)を返すので、アプリが再試行を続けてしまいます
- **Resend** は共有ドメインだと `+` エイリアスすら「自分のアドレス」と認めないほど厳密でした
- **SMTP2GO** はそもそも登録できませんでした。`Please use an email at your own domain to sign up` と言われます

## 4. API

### 候補に挙がったもの(10)

| 区分 | サービス |
|---|---|
| **選んだ 4 つ** | **Cloud Run、Render、Back4App、Northflank** |
| 無料では実用にならなかった | Zeabur(検証時は無料で始められず)、Railway(毎月 $1 分のクレジットのみ)、Fly.io(新規向け無料枠が廃止) |
| 登録できなかった | Koyeb |
| 権限とネットワークの設計が要る | AWS App Runner / ECS、Azure Container Apps |

### なぜこの 4 つか

ここは候補の入れ替えが一番多かった層です。条件は「Docker イメージをそのまま動かせること」でした。

当初の案には **Zeabur**(東京・日本語 UI)と **Koyeb**(東京で DB と同居できる唯一の無料 PaaS)が入っていました。ところが Zeabur は有料だと分かり、Koyeb は利用登録ができませんでした。Fly.io と Railway も無料では始められません。AWS と Azure は、個人がひとりで持つには設計が重すぎます。

そうやって残ったのがこの 4 つです。

- **Render** は手数が最少でカード不要、フロントとも同居できるので、当初の第一候補でした
- **Cloud Run** は無料枠が最大で東京に置けて、メモリも自由に設定できます。ただしカード必須で、超えると課金されます
- **Northflank** は無料枠でも常時起動します。常駐ワーカーが動くかを見たかった
- **Back4App** はカード不要の定額制で、「請求リスクゼロ」の代表として入れました

途中の案では Cloud Run を 2 つの構成で測るつもりでしたが、別のサービスを 4 つ見たほうが記事として価値があるので、Back4App に差し替えました。

### 4 社の顔ぶれ

**Cloud Run**(Google・米)は、コンテナをフルマネージドで動かす基盤です。無料枠は 200 万リクエスト/月、vCPU 18 万秒、メモリ 36 万 GiB 秒ですが、**課金アカウント(カード)が必須です**。超えると従量課金で、vCPU $0.000024/秒、メモリ $0.0000025/GiB 秒です。要求がない間は 0 に縮んで処理中だけ課金されます。予算アラートは通知するだけなので、支払いを止めるには自分で自動化する必要があります。

**Render**(米)は、Git 連携中心の PaaS です。無料枠は 750 時間/月、512MB で、15 分無通信でスリープします。カードは要りません。有料は $7/月(0.5 CPU・512MB)からです。公式が「無料枠は本番に使わないこと」と明記しています。

**Back4App**(米・ブラジル拠点)は、Docker アプリを GitHub から配備する PaaS です。無料枠は 0.25 CPU、256MB、転送 100GB/月で、リージョンは US のみ、カードは要りません。有料はコンテナ単位の定額で $5/月(0.5 CPU・512MB)からです。従量ではないので請求が読めます。

**Northflank**(英)は、複数クラウドにまたがって配備できる開発基盤です。無料枠はサービス 2 つ・DB 1 つ・cron 2 つで、スリープせず、カードも要りません。有料は従量で、最安 $5.40/月(0.2 vCPU・512MB)です。自前クラウドへの配備(BYOC)にも対応しています。

### 実測

同じ本番用イメージ(distroless、31MB)を 4 社に置き、DB・写真・メールはすべて同じものを向けました。

| 候補 | 立地 | 往復 | DB あり | 写真 24MP | SMTP |
|---|---|---|---|---|---|
| **Cloud Run** | 東京 | **46ms** | 287ms | **3.5 秒で通る** | **通る** |
| Render | オレゴン | 147ms | 322ms | 502 | **塞がれている** |
| Back4App | 米国 | 193ms | 421ms | 502 | 通る |
| Northflank | US | 479ms | 864ms | 503 | 通る |

**全機能が動いたのは Cloud Run だけでした。**

個人開発で一番怖いのは事故で請求が来ることなので、最初は「上限で止まるだけの無料プラン」を高く評価していました。ところがその基準で選んだ 3 社はどれもアプリを動かせず、動いたのはカード必須で超過すると課金される Cloud Run だけでした。**「請求リスクなし」と「機能が動く」は両立しませんでした。**

写真の列は、API を直接叩いて原寸(2,400 万画素)を送った結果です。ブラウザ経由なら送信前に 1600px に縮小されるので、無料プランでも通ります。ただし縮小に失敗すると原寸が飛ぶので、守りとしては弱いです。

### ハマったこと

- **Render** は `render.yaml` にシンガポールと書いてもオレゴンになり、後から変えられません。Root Directory を `backend-go` にしないと `go.sum not found` で落ちます。SMTP が塞がれているのでサインアップが完結しません
- **Northflank** は無料枠だと US しか選べません(Asia は有料です)。384 万画素で 33 秒かかり、落ちる前に極端に遅くなりました
- **Back4App** は Dockerfile の名前を選べず、既定の `Dockerfile` だけを見ます。一時 URL が期限切れになるので、継続運用はできませんでした
- **Cloud Run** は要求がない間インスタンスが 0 になるので、常駐ワーカーも止まります

事前調査では「SMTP を塞ぐのは Cloud Run」と書いていました。実測すると塞いでいたのは Render でした。**ポートの遮断は事業者が明記しないことが多く、実測でしか分かりません。**

## 5. フロントエンド

### 候補に挙がったもの(17)

| 区分 | サービス |
|---|---|
| **選んだ 4 つ** | **Cloudflare Workers、Render Static、Netlify、Vercel** |
| `/api` のリライトができない | GitHub Pages、Firebase Hosting(Cloud Functions 先限定)、Surge、GitLab / Codeberg Pages、Azure Static Web Apps |
| 無料枠がない、または期限付き | S3 + CloudFront、Amplify、Bunny、DigitalOcean App Platform(帯域 1GB/月) |
| 静的配信にコンテナは過剰 | Fly.io / Railway に nginx、Koyeb / Zeabur |
| 目的が違う | Coolify / Dokploy(セルフホスト)、IPFS |

### なぜこの 4 つか

フロントは `/api` を同一オリジンで叩く前提なので、「`/api/*` を外部の URL へリライトできること」が条件です。これでかなり落ちました。残った中から、**設定の書き方が違う 4 社**を選んでいます。

- **Cloudflare Workers** は、設定ではなくコードでリライトを書く唯一の方式です。帯域無制限・商用可も 4 社で唯一でした
- **Render Static** は YAML で宣言する方式で、API と同居できる当初の第一候補でした
- **Netlify** は記述量の少なさの代表です。「1 行で書ける」という評判が性能とどう関係するかを見たかった
- **Vercel** は最も普及しているので、避ける理由があるなら示す価値があると考えました

### 4 社の顔ぶれ

**Cloudflare Workers**(米・上場)は、Workers に静的ファイルを同梱して CDN 配信する仕組みです。Worker 呼び出しは 10 万回/日までですが、**静的アセットへの要求と帯域は無料・無制限**で、商用利用もできます。有料は Paid $5/月(1,000 万リクエスト込み)です。Worker を通す分(`/api/*` の転送)だけが日次上限に掛かります。

**Render Static**(米)は、Git からビルドして CDN 配信するサービスです。静的サイト自体は無料で、帯域とビルド分数がワークスペースの枠に計上されます(検証時の記録では帯域 100GB/月でした)。課金は超過分だけです。API と同じ基盤に同居できますが、CLI はなく Git 連携だけです。

**Netlify**(米)は、静的サイト・フロントエンドのホスティングです。無料枠は 300 クレジット/月で、帯域に換算すると約 15GB 相当です。使い切ると全サイトが止まります。商用利用はできます。有料は Personal $9/月(1,000 クレジット)です。2025 年 9 月にクレジット制に変わり、無料枠の帯域が大きく縮みました。

**Vercel**(米)は、フロントエンド向けのホスティングとサーバーレスです。無料枠は転送 100GB/月、100 デプロイ/日と最大級ですが、**個人・非商用のみ**で、広告や決済を含む商用は規約で禁止されています。有料は Pro $20/月です。

### 実測

同じビルド成果物(496KB)を 4 社に置き、`/api/*` を Cloud Run へ転送する設定を入れました。

| 候補 | HTML | API 転送 | 設定 | デプロイ所要 |
|---|---|---|---|---|
| **Cloudflare Workers** | 54ms | **285ms** | JS 11 行 | **約 8 秒** |
| Render Static | **40ms** | 505ms | YAML 7 行 | push 後 約 1 分 |
| Netlify | 287ms | **827ms** | TOML 9 行 | 8〜71 秒 |
| Vercel | 44ms | **148ms** | JSON 10 行 | 約 25 秒 |

参考として、API 直叩きは 288ms でした。

**HTML の速さと転送の速さは連動しません。** Render は HTML が最速なのに転送は 3 位です。静的配信の速さだけで選ぶと、API 経由で損をします。

Cloudflare だけがコードを書く方式なので減点していましたが、行数の差は 4 行でした。しかも転送は最速です。**「コードを書く手間」は減点になりませんでした。**

### ハマったこと

- **Cloudflare** では Google ログインが 2 段構えで壊れました。ページ遷移だとアセット配信が Worker より先に働くのと、`fetch` が 302 を勝手に追いかけるのと、原因が 2 つあります。`run_worker_first` と `redirect: "manual"` の両方が要り、片方だけ直しても症状が変わりません
- **Render** は Action を Redirect にするとオリジンが変わって CORS で失敗します。Rewrite にする必要があります
- **Vercel** は既定で非公開(SSO に 302)でした。50 回のリクエストで Bot 対策に遮断され、CLI で配ると本番 URL が毎回変わります
- **Netlify** ではハマりませんでした。ただし転送が突出して遅く、デプロイ時間も 8 秒から 71 秒まで振れます

デプロイの所要時間は「コマンドが終わった」と「反映された」が別です。Render は push が 1 秒で戻り、ビルドは向こうで非同期に走ります。反映の確認は、ハッシュではなく変えた値そのものを配信物から探すのが確実でした。

## 選んだ構成

「全機能が動く」を最優先にして、その上で長期の費用と安全側に倒しました。

| 層 | 採用 | 選ばなかった最有力と、その理由 |
|---|---|---|
| API | Cloud Run(東京、1GB) | Render は写真と SMTP が動かず、サインアップが完結しませんでした |
| DB | Neon | Supabase は東京で作り直せば速いはずですが、1 週間で停止します |
| 写真 | Cloudflare R2 | Tigris は 3 倍速いのですが、転送量が従量です |
| メール | Resend | Mailjet は関門がなさすぎて、鍵の漏洩と設定ミスに弱いです |
| フロント | Cloudflare Workers | Vercel は転送最速ですが、非商用限定・既定で非公開・Bot 対策の 3 つが重いです |

カード登録なしで完結する構成は組めませんでした。Cloud Run と R2 はカードが要ります。予算アラートは支払いを止めないので、上限を超えたときに自分で止める覚悟は要ります。

残った課題は統計の再計算ワーカーです。Cloud Run は要求がない間インスタンスが 0 になるので、誰も見ていない間はワーカーも止まります。最小インスタンスを 1 にするか、外部の cron から叩くかのどちらかになります。

## 付録: 選ばなかったサービスの概要

本文では各層 4 つに絞りましたが、前提が違えば別のサービスのほうが合う人もいるはずです。候補に挙がったものについて、運営・何のサービスか・無料枠か最安料金・どういう人に向くかを、公式ページで確かめてまとめました(2026 年 9 月時点)。

### データベース(選ばなかった 16)

今回の条件は「Postgres のワイヤプロトコルで、外部キー・UUID・`FOR UPDATE SKIP LOCKED` がそのまま動くこと」でした。

**技術的に使えなかった**

**Amazon Aurora DSQL**(AWS・米)は、PostgreSQL 互換のサーバーレス分散 SQL です。毎月 10 万 DPU と 1GB が無料で、超えると 100 万 DPU あたり $8 です。外部キーとシーケンスに対応していないので外しましたが、リージョンをまたいで止まらない構成を最初から欲しい人には向きます。

**Cloudflare D1**(Cloudflare・米)は、SQLite の SQL を持つ Workers 向けのサーバーレス DB です。無料で読み 500 万行/日、書き 10 万行/日、5GB まで使えます。Workers の中からしか使えないので Go の API には合いませんでしたが、アプリ本体を Workers に置く人には自然な選択です。

**MongoDB Atlas**(MongoDB, Inc.)は、マネージドのドキュメント DB です。M0 は 512MB で永久無料、有料は Flex が $0.011/時からです。JSON 中心のスキーマで、リレーションや外部キーを必要としない人に向きます。

**Amazon DynamoDB**(AWS・米)は、サーバーレスのキーバリュー DB です。常時無料枠が 25GB、25 WCU・25 RCU と大きめです。アクセスパターンが決まっていて、キー指定の読み書きが中心の AWS 利用者に向きます。

**別の道具に乗り換えることになる**

**PlanetScale**(米)は、MySQL(Vitess / Neki)と PostgreSQL のマネージド DB です。無料枠はなく、最安は Postgres の単一ノード PS-10 で $10/月です。月 $10 を払えて、将来シャーディングまで見据える人に向きます。

**TiDB Cloud Starter**(PingCAP・米)は、MySQL 互換のサーバーレス分散 SQL です。無料枠は 1 インスタンスあたり 5GiB + 5GiB、5,000 万 RU/月と大きく、東京も選べます。MySQL 互換でよく、無料枠の大きい分散 DB を試したい人に向きます。

**Turso**(米)は、SQLite / libSQL 系のマネージド DB です。無料で 5GB、DB 100 個、読み 5 億行/月まで使え、カードも要りません。SQLite の手軽さのまま、DB を多数作ったりエッジ寄りに置きたい人に向きます。

**Litestream**(Ben Johnson 氏の OSS。Fly.io が支援)は、SQLite の変更を S3 などへ継続的に複製するツールで、DB サービスではありません。ソフトは無料で、費用は複製先のストレージ代だけです。単一 VM + SQLite で運用し、バックアップだけ欲しい人に向きます。

**要件に対して過剰**

**CockroachDB Cloud**(Cockroach Labs・米)は、PostgreSQL ワイヤ互換の分散 SQL です。Basic は毎月 $15 相当(5,000 万 RU + 10GiB)が無料ですが、カード登録が前提です。Postgres 互換のまま、地理分散と水平スケールが要件の人に向きます。

**YugabyteDB Aeon**(Yugabyte・米)は、PostgreSQL 互換の分散 SQL です。Sandbox は 2 vCPU・4GB・10GB が永久無料でカード不要ですが、単一ノード・バックアップなし・10 日無操作で停止と、公式が本番には不向きと明記しています。分散 Postgres を学習・検証したい人に向きます。

**他と差がつかない**

**Aiven for PostgreSQL**(Aiven・フィンランド)は、素の PostgreSQL のマネージドサービスです。無料枠は 1 CPU・1GB RAM・1GB で期限がなく、有料は $5/月からです。EU 企業の運営で素の Postgres を使いたい人や、1GB で足りる小規模な用途に向きます。

**Prisma Postgres**(Prisma Data, Inc.)は、操作数で課金するマネージド PostgreSQL です。無料で 500MB、20 万操作/月まで使え、カード不要です。Prisma ORM を使う TypeScript アプリで、DB とホスティングを 1 か所にまとめたい人に向きます。

**Nile**(Nile Platform・米)は、マルチテナントの B2B アプリ向けサーバーレス PostgreSQL です。無料で 1GB、5,000 万クエリトークン/月まで使えます。テナント分離を DB 側で担保したい SaaS 開発者に向きます。

**無料で始められない・運用が重い・登録できなかった**

**Fly.io Managed Postgres**(Fly.io・米)は、Fly.io 上のマネージド PostgreSQL です。無料枠はなく、最安は Basic $38/月です。アプリを Fly.io に置いていて、同じ基盤で DB も運用したい人に向きます。

**Oracle Cloud Always Free**(Oracle)は、Autonomous Database 2 個と Arm の VM(合計 2 OCPU・12GB)などを期限なしで無料提供する枠です。DB は Oracle DB で Postgres 互換ではなく、VM に自分で Postgres を入れることになります。7 日間の使用率が 20% 未満の VM は回収されます。OS の更新やバックアップを自分で持ってよい人に向きます。

**Koyeb Postgres**(Koyeb)は、Koyeb のマネージド PostgreSQL で、5 分無操作でスリープします。free インスタンスは 1GB・コンピュート 5 時間/月までです。検証時は利用登録ができませんでした。Koyeb にアプリを置いていて、常時稼働しない検証用 DB でよい人に向きます。

### 写真ストレージ(選ばなかった 16)

今回の条件は「S3 互換の `PutObject` / `DeleteObject` で書けて、公開 URL から配信でき、転送量の課金が軽いこと」でした。

**S3 互換でない(コードを書き足す)**

**Vercel Blob**(Vercel・米)は、Vercel のプロジェクト向けオブジェクトストレージです。独自 SDK(`@vercel/blob`)で使い、S3 互換 API はありません。Hobby は保存 1GB、転送 10GB/月まで無料で、超えると課金ではなく 30 日間使えなくなります。フロントも Vercel に置いて Next.js から SDK だけで完結させたい人に向きます。

**Cloudflare Images**(Cloudflare・米)は、画像の保存・変換・配信に特化したサービスです。変換は月 5,000 ユニークまで無料で、保存は $5/10 万枚月、配信は $1/10 万枚です。リサイズや形式変換をサーバーで持ちたくない人、画像枚数で料金を読みたい人に向きます。

**Bunny Storage**(BunnyWay・欧州)は、CDN 直結のファイルストレージです。API は独自の HTTP REST で S3 互換ではありません。無料枠はなく 14 日の試用で、以降は $0.01/GB 月、月額最低 $1 です。Bunny CDN への転送は無料なので、月 $1 台から CDN 込みで安く済ませたい人に向きます。

**用途が違う(画像変換に特化)**

**ImageKit**(ImageKit Private Limited・インド)は、画像・動画の変換と CDN 配信の層です。S3 や Wasabi など外部ストレージの前段に置けます。無料枠は帯域 20GB/月・保存 3GB で期限がなく、有料は $9/月からです。既存の S3 互換バケットを残したまま、URL パラメータで変換を足したい人に向きます。

**Cloudinary**(米)は、画像・動画の管理・AI 変換・配信の SaaS です。無料は 25 クレジット/月(変換 1,000 回か保存 1GB か帯域 1GB が 1 クレジット)でカード不要ですが、有料は $89/月からと段差が大きいです。画像の加工が主機能の人に向きます。

**Uploadcare**(米)は、アップロード UI・保存・画像処理・CDN をまとめたプラットフォームです。無料は操作 1,000 回/月・保存 1GB・転送 5GB で個人利用のみ、有料は $66/月からです。アップロードのウィジェットまで用意してほしい人に向きます。

**UploadThing**(Ping Labs)は、TypeScript アプリ向けのアップロード SaaS です。無料で保存 2GB、有料は $10/月(100GB)です。フロントもバックも TypeScript で、認可付きのアップロードを数行で済ませたい人に向きます。

**無料枠がない、または期限付き**

**Amazon S3**(AWS・米)は、S3 API の本家です。2025 年 7 月以降の新規は「6 か月・最大 $200 のクレジット」方式で、以降は保存 $0.0265/GB 月、インターネットへの転送 $0.09/GB です。実績と周辺エコシステムを最優先する人に向きますが、転送の単価が重いです。

**Google Cloud Storage**(Google)は、XML API が S3 互換ツールと相互運用できます。Always Free は米国リージョン限定で保存 5GB、北米からの転送 100GB/月です。米国リージョンでよく、転送 100GB/月に収まる小規模な用途なら実質無料にできます。

**Azure Blob Storage**(Microsoft)は、Azure のオブジェクトストレージで、独自 REST API です。無料アカウントは $200 クレジット(30 日)+ 12 か月の無料枠で、カードが必須です。すでに Azure に寄せていて、Azure SDK で書くことに抵抗がない人に向きます。

**Wasabi**(米)は、egress と API 呼び出しが無料の S3 互換ストレージです。無料枠はなく、$7.99/TB 月で最低課金が 1TB 分です。数 TB 以上を置く人に向きますが、数 GB の個人アプリだと $7.99/月が固定で乗ります。

**DigitalOcean Spaces**(米)は、CDN 内蔵の S3 互換ストレージです。無料枠はなく、$5/月で保存 250GiB・転送 1TiB が込みです。月 $5 固定で CDN 込みの転送枠を確保したい人に向きます。

**Hetzner Object Storage**(Hetzner・ドイツ)は、欧州 3 拠点の S3 互換ストレージです。無料枠はなく、基本料金に保存 1TB と egress 1TB が含まれます(金額はページから取得できず)。EU にデータを置きたい人、TB 級の egress が要る人に向きます。

**運用が重い、条件が読めない**

**MinIO**(MinIO, Inc.・米)は、自前で動かす S3 互換ストレージのソフトウェアです。旧 AGPLv3 の OSS 版はメンテナンス終了と明記され、現在は AIStor Free(単一ノード)が無料です。開発環境で S3 API を再現したい人に向きます(本検証でもツールの動作確認に使いました)。

**Storj**(米)は、分散型の S3 互換ストレージです。30 日の試用のあとは保存 $7/TB 月、egress $7/TB で、最低課金 $5/月です。TB 級で安く、地理分散を重視する人に向きます。

**Render Disks**(Render)は、サービス 1 インスタンスにマウントするブロックストレージです。$0.25/GB 月で、無料の Web サービスには付けられず、付けると水平スケールとゼロダウンタイムデプロイができなくなります。ローカルディスク前提のコードをそのまま動かしたい人に向きます。

### メール送信(選ばなかった 12)

今回の条件は「SMTP で送れて、フリーメールの個人が登録でき、無料で始められること」でした。調べ直してみると、Mailgun と Elastic Email には十分な無料枠があり、当初の「試用のみ」という把握は正確ではありませんでした。

**登録の障壁で失格**

### フロントエンド(選ばなかった 13)

今回の条件は「`/api/*` を外部の API へリライト(200 でプロキシ)できること」でした。できないものでも、API を CORS で別ドメインから直接叩く構成なら使えます。

**外部 URL へのリライトができない**

**GitHub Pages**(GitHub・米)は、リポジトリから静的サイトを公開するホスティングです。リライト機能はなく、静的配信だけです。無料でサイト 1GB、帯域 100GB/月のソフト上限があり、EC や SaaS の商用ホスティングは禁止されています。OSS のドキュメントやポートフォリオに向きます。

**Firebase Hosting**(Google・米)は、CDN 付きの静的 / SPA ホスティングです。rewrites の宛先はローカルファイル・Cloud Functions・Cloud Run に限られます。Spark は保存 10GB、転送 360MB/日でカード不要です。API も Cloud Run に置くなら、`/api/**` を同一オリジンで rewrite できます。今回の構成なら実は成立する選択肢です。

**Surge.sh**(Chloi Inc.)は、CLI 1 コマンドで公開する静的ホスティングです。外部へのプロキシはドキュメントに記載がなく確認できませんでした。無料プランは公開無制限・カスタムドメイン可で、Professional は $30/月です。とにかく速く試作を公開したい人に向きます。

**GitLab Pages**(GitLab・米)は、GitLab の CI/CD から静的サイトを公開する機能です。`_redirects` で内部パスへの 200 リライトはできますが、外部ドメインは 301/302 だけです。Free はカード不要でコンピュート 400 分/月です。すでに GitLab で CI を回しているチームに向きます。

**Codeberg Pages**(Codeberg e.V.・独・非営利)は、FLOSS 向けの無料 Git ホスティングに付属する静的サイト公開です。外部 URL への 200 は「no external URLs」と明記されています。寄付で運営され完全無料ですが、掲載できるのは FLOSS ライセンスのプロジェクトだけです。OSS で EU 拠点の非営利インフラを使いたい人に向きます。

**Azure Static Web Apps**(Microsoft・米)は、GitHub 連携の静的ホスティング + Functions 連携です。rewrite の宛先はアプリ内の相対パスに限られます。Free は帯域 100GB/月でアプリ 10 個までですが、「個人・趣味向け」とされています。API を Azure Functions や Container Apps に置ける人に向きます。

**DigitalOcean App Platform(Static Sites)**(DigitalOcean・米)は、Git 連携 PaaS の静的サイト部品です。ルーティングは同じアプリ内のコンポーネントか redirect だけです。静的サイトだけのアプリを 3 個まで無料で、各 1GiB/月の転送です。API も同じ App Platform に置き、同一アプリ内でルーティングしたい人に向きます。

**リライトはできるが、無料枠がないか期限付き**

**Amazon S3 + CloudFront**(AWS・米)は、S3 の静的ファイルを CloudFront で配信する構成です。CloudFront は任意の HTTP(S) サーバーをオリジンにでき、パス別に振り分けられるので、`/api/*` のプロキシはできます。CloudFront の Free プランは転送 100GB・S3 5GB で超過課金なしですが、AWS アカウント自体に決済手段の登録が要ります。AWS に慣れていて、IaC で CDN・WAF まで自分で組みたい人に向きます。

**AWS Amplify Hosting**(AWS・米)は、Git 連携のフルマネージド静的 / SSR ホスティングです。「Reverse proxy rewrite」で外部 URL への 200 リライトができます。無料枠は 12 か月限定で、以降は配信 $0.15/GB です。12 か月後の従量課金を許容できれば、今回の条件も満たします。

**bunny.net**(BunnyWay・欧州)は、低価格 CDN とオブジェクトストレージです。Edge Rules の「Change Origin URL」でパス単位に別オリジンへ流せます。恒久の無料枠はなく 14 日の試用で、以降は月最低 $1、アジア向け $0.03/GB です。月数ドルの実費でよく、CDN の設定を自分で握りたい人に向きます。
