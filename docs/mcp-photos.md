# MCP から写真つきレビューを投稿する

既存の `create_review` と `update_review` に、任意の `photo_base64` を渡せる。
利用者は、画像ファイルを指定するか、元の画像データを扱えるクライアントで写真を添付して、店名・バーガー名・評価・本文を伝える。

- 新規投稿: `create_review` に写真を渡すと、レビューと一緒に保存する。
- 写真の追加・差し替え: `update_review` にレビュー ID、評価、本文、写真を渡す。実食日を維持する場合は現在の値も渡す。
- 写真を省略した編集: 保存済みの写真を保持する。
- 1レビューに写真は1枚。複数のレビューは1件ずつ呼び出す。

写真は通常の画面投稿と同じ検査・縮小・保存処理を通る。対応形式は JPEG / PNG / WebP。
サイズ上限は `get_meta` の写真の情報で確認する。
空文字や不正な画像を送った場合は、レビューを作成・変更せずにエラーを返す。
写真の削除は、この入力では行えない。

## MCP クライアント側の処理

`photo_base64` は、画像ファイルの実バイトを標準 Base64 でエンコードした文字列。
URL、PC内のパス、`data:image/...;base64,` の接頭辞は渡さない。
元データの取得とエンコードはクライアントのファイル処理機能で行い、モデルに文字列を推測・生成させない。
利用者が手で Base64 を作る必要はない。

クライアントが元の添付画像を読み取れない場合、チャットで画像を表示できてもそのまま投稿はできない。
ファイルを読み取れるクライアントから送る必要がある。
クライアント独自のツール引数のサイズ制限が、サーバーの写真上限より小さい場合もある。

呼び出し例（`encodedImage` はクライアントが読み取った画像をエンコードした値）:

```js
await session.callTool({
  name: "create_review",
  arguments: {
    shop_id: shopId,
    burger_id: burgerId,
    rating: 4,
    comment: "肉がジューシーでした",
    photo_base64: encodedImage,
  },
});
```

書き込みには従来と同じ書き込みスコープが必要で、編集できるのは投稿者本人だけ。
MCP の POST 本文には、写真の Base64 増分と JSON のための余裕を含む上限があり、
上限を超えると HTTP 413 になる。通常の REST JSON API の本文上限は変わらない。
