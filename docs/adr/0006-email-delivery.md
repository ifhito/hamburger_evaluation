# ADR-0006: メール送信サービス

- ステータス: 提案中(Proposed)
- 日付: 2026-09-21
- 対象: `backend-go` が送るサインアップ確認メール
- 方針: **無料で始める**
- 関連: [ADR-0002](0002-backend-deploy-target.md)、[ADR-0003](0003-database-hosting.md)

## 背景

初版の ADR 群(0001〜0005)にこの層が抜けていた。実装を読んで判明した。

### 実装されている仕組み

- `internal/adapter/infra/smtp.go` が **SMTP** で送る。API 送信ではない。
- `async_mailer.go` が非同期に送り、`mail_deliveries` テーブルに結果を記録する。
- 冪等キー(`idempotency_key`)が UNIQUE なので、同じ要求では 1 通しか出ない。
- 本文・確認トークン・パスワードは保存しない。記録は種別・宛先・状態・失敗理由だけ。
- 種別は 2 つ。`signup_confirmation`(サインアップ確認)と `already_registered`(既に登録済みの通知)。
- 失敗は `temporary`(再試行で直りうる)と `permanent`(直らない)に分かれる。
- 開発環境には mailpit が同梱されており、`http://localhost:8025` で受信箱を読める。

### 環境変数

| 変数 | 内容 |
|---|---|
| `SMTP_HOST` / `SMTP_PORT` | 送信先のサーバー |
| `SMTP_USER` / `SMTP_PASSWORD` | 認証情報 |
| `SMTP_SECURITY` | 暗号化方式(`tls` / `starttls` / `none`) |
| `MAIL_FROM` | 差出人 |

### 送信ポートが塞がれている場合がある

**これが本 ADR の最大の論点である。** 多くの PaaS が迷惑メール対策で外向きの SMTP を制限する。

- Google Cloud Run: ポート **25 / 587 / 465 を塞ぐ**。SMTP は使えない。
- Render / Zeabur: 明示の記載が乏しく、**実測が必要**。

塞がれている場合の選択肢は 2 つ。

- A. 事業者が許す代替ポートを使う(`SMTP_SECURITY=tls` で 465 に切り替えるなど)
- B. **SMTP をやめて HTTP API 送信に切り替える**。`infra/smtp.go` と同じインターフェースの実装を足す

B は実装作業が発生するため、**SMTP が通るホストを選べるならそのほうが安い**。

## 評価軸

1. **無料枠の通数**(月あたり・日あたり)と期限
2. **SMTP で送れるか**(API 専用のサービスもある)
3. HTTP API 送信の有無(上記 B の逃げ道になるか)
4. 独自ドメインの要否と、SPF / DKIM の設定量
5. 到達率(迷惑メール判定されにくいか)
6. カード登録の要否

## 無料で始められる候補

条件は 2026-09 時点の目安。契約前に公式で再確認すること。

| 候補 | 無料枠 | SMTP | API | 独自ドメイン | 所感 |
|---|---|---|---|---|---|
| Resend | 3,000 通/月、100 通/日 | ◎ | ◎ | 独自ドメイン推奨。検証用の共有ドメインあり | 個人開発者向けで設定が最も軽い |
| Brevo(旧 Sendinblue) | **300 通/日**(無期限) | ◎ | ◎ | 不要でも送れる | 無料枠の通数が最大。UI は多機能で重め |
| SendGrid | 100 通/日 | ◎ | ◎ | 要設定 | 老舗で情報が多い。無料枠の条件が変動しがち |
| Mailgun | 試用後は従量 | ◎ | ◎ | 要設定 | 無料枠が実質ない |
| Amazon SES | 3,000 通/月(12 か月)。以後 $0.10/1,000 通 | ◎ | ◎ | 要設定 | 安いがサンドボックス解除の申請が要る |
| Postmark | 試用 100 通/月 | ◎ | ◎ | 要設定 | 到達率は最高水準だが無料枠が小さい |
| Gmail SMTP(アプリパスワード) | 500 通/日 | ◎ | ✕ | 不要 | 設定は最短。ただし**業務利用は規約上グレー** |

### 所感

- **Resend**: 個人開発者向けに作られており、独自ドメインの検証も画面の指示どおりで済む。
  SMTP と API の両方に対応しているので、ホストがポートを塞いでいても実装を足せば逃げられる。
- **Brevo**: 300 通/日は本アプリ(サインアップ確認のみ)には十分すぎる。無料枠の寿命が最も長い。
- **SendGrid**: 情報量は最多。ただし無料枠の条件変更が過去に何度かあった。
- **Gmail SMTP**: 検証段階の暫定手段としては有効。本番では使わない。
- **SES / Postmark / Mailgun**: 手数か無料枠のどちらかで個人開発には合わない。

## 決定(案)

**Resend** を第一候補、**Brevo** を通数が必要になったときの代替とする。

- どちらも SMTP で送れるため、`infra/smtp.go` をそのまま使える。実装変更が不要。
- どちらも HTTP API を持つため、ホストが SMTP を塞いでいた場合の逃げ道がある。
- 検証の初期は mailpit(ローカル)で疎通だけ確認し、そのあと実サービスに切り替える。

**API が Cloud Run の場合はこの決定が成立しない。** SMTP が塞がれているため、API 送信の実装が必須になる。
これは [ADR-0002](0002-backend-deploy-target.md) で Cloud Run の順位を下げた理由の 1 つである。

## 結果・影響

- 設定するもの: `SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_SECURITY`、`MAIL_FROM`。
  コード変更は不要。認証情報は環境変数で渡し、リポジトリに書かない。
- **独自ドメインと SPF / DKIM の設定が要る。** 共有ドメインのままだと迷惑メール判定されやすい。
  フロントのドメイン(ADR-0001)を決めたあとに設定する。
- **ホストごとに SMTP の疎通確認が要る。** 机上では分からないため、Phase 4 で実測する。
- `mail_deliveries` は行が溜まる。削除ジョブを [ADR-0005](0005-async-job-platform.md) の
  `cleanup-expired` に含める。
- 送信失敗時の扱いは実装済み(`temporary` / `permanent` の区別と再試行)。本 ADR では変更しない。
