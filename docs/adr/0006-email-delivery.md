# ADR-0006: メール送信サービス

- ステータス: 提案中(Proposed)
- 日付: 2026-09-21
- 対象: `backend-go` が送るサインアップ確認メール
- 方針: **無料で始める**
- 関連: [ADR-0002](0002-backend-deploy-target.md)、[ADR-0003](0003-database-hosting.md)

## 背景

初版の ADR 群(0001〜0005)にこの層が抜けていた。実装を読んで判明した。

### 実装されている仕組み

- `internal/adapter/infra/smtp.go` が **SMTP** で送る。API 送信ではない。
- `async_mailer.go` が非同期に送り、`mail_deliveries` テーブルに結果を記録する。
- 冪等キー(`idempotency_key`)が UNIQUE なので、同じ要求では 1 通しか出ない。
- 本文・確認トークン・パスワードは保存しない。記録は種別・宛先・状態・失敗理由だけ。
- 種別は 2 つ。`signup_confirmation`(サインアップ確認)と `already_registered`(既に登録済みの通知)。
- 失敗は `temporary`(再試行で直りうる)と `permanent`(直らない)に分かれる。
- 開発環境には mailpit が同梱されており、`http://localhost:8025` で受信箱を読める。

### 環境変数

| 変数 | 内容 |
|---|---|
| `SMTP_HOST` / `SMTP_PORT` | 送信先のサーバー |
| `SMTP_USER` / `SMTP_PASSWORD` | 認証情報 |
| `SMTP_SECURITY` | 暗号化方式(`tls` / `starttls` / `none`) |
| `MAIL_FROM` | 差出人 |

### 送信ポートが塞がれている場合がある

**これが本 ADR の最大の論点である。** 多くの PaaS が迷惑メール対策で外向きの SMTP を制限する。

- Google Cloud Run: ポート **25 / 587 / 465 を塞ぐ**。SMTP は使えない。
- Render / Zeabur: 明示の記載が乏しく、**実測が必要**。

塞がれている場合の選択肢は 2 つ。

- A. 事業者が許す代替ポートを使う(`SMTP_SECURITY=tls` で 465 に切り替えるなど)
- B. **SMTP をやめて HTTP API 送信に切り替える**。`infra/smtp.go` と同じインターフェースの実装を足す

B は実装作業が発生するため、**SMTP が通るホストを選べるならそのほうが安い**。

## 評価軸

1. **無料枠の通数**(月あたり・日あたり)と期限
2. **SMTP で送れるか**(API 専用のサービスもある)
3. HTTP API 送信の有無(上記 B の逃げ道になるか)
4. 独自ドメインの要否と、SPF / DKIM の設定量
5. 到達率(迷惑メール判定されにくいか)
6. カード登録の要否

## 無料で始められる候補

条件は 2026-09 時点の目安。契約前に公式で再確認すること。

| 候補 | 無料枠 | SMTP | 独自ドメイン | 所感 |
|---|---|---|---|---|
| **Mailjet** | **6,000 通/月、200 通/日** | ◎ | 不要(送信者アドレスの認証で可) | 比較した中で無料枠が最大。EU 系(Sinch 傘下) |
| **Resend** | 3,000 通/月、100 通/日 | ◎ | 本番は必要 | 開発者向けで設定が最軽量。共有ドメインは自分宛にしか送れない |
| **MailerSend** | 3,000 通/月 | ◎ | 本番は必要 | MailerLite の配信部門。試用ドメインあり |
| **SMTP2GO** | 1,000 通/月 | ◎ SMTP 専業 | 不要 | 到達率を売りにする。設定が単純 |
| Brevo | 300 通/日 | ◎ | 不要 | 無料枠の寿命は長いが UI が多機能で重い |
| Scaleway TEM | 300 通/月 | ◎ | 必要 | EU リージョンのみ |
| Elastic Email | 100 通/日 | ◎ | 不要 | 安価だが到達率の評判が割れる |
| SendGrid | 100 通/日 | ◎ | 不要 | **新規の無料アカウントが審査で止まる事例が多い** |
| Amazon SES | 3,000 通/月(12 か月) | ◎ | 必要 | サンドボックス解除の申請が要る |
| Mailgun | 試用のみ | ◎ | 必要 | かつて 5,000 通/月が無料だったが廃止された |
| Postmark | 試用 100 通/月 | ◎ | 必要 | 到達率は最高水準だが無料枠が小さい |
| ZeptoMail(Zoho) | なし | ◎ | 必要 | 10,000 通で 2.5 ドル。有料では最安級 |
| Gmail SMTP | 500 通/日 | ◎ | 不要 | **アプリからの自動送信は規約上グレー**。差出人が個人アドレスで固定 |

### 所感

- **Mailjet**: 無料枠が最大(6,000 通/月)で、送信元はアドレス 1 つの認証で足りる。
  独自ドメインを持たない段階でも本番相当の運用ができる
- **Resend**: 設定が最も軽く、SMTP と API の両方に対応する。ただし共有ドメイン
  `onboarding@resend.dev` は**登録したアドレス宛にしか送れない**ため、他人にメールを
  送る段階で独自ドメインが要る
- **MailerSend**: 3,000 通/月。メール配信の会社が出す transactional 部門という出自で、
  到達率まわりの機能が厚い
- **SMTP2GO**: SMTP 専業で、設定項目が少なく詰まりにくい。無料枠は 1,000 通/月と
  控えめだが、本アプリ(サインアップ確認のみ)には十分
- **Brevo**: 300 通/日で無期限。条件は良いが UI がマーケティング機能中心で重い
- **SendGrid**: 情報量は最多だが、**新規の無料アカウントが審査で止まる報告が多い**。
  登録できるかどうか自体が不確実なため、第一候補にはしない
- **Gmail SMTP**: 設定は最短だが、アプリからの自動送信は Google の規約上グレーで、
  差出人が個人のアドレスに固定される。**本番では使わない**
- **SES / Postmark / Mailgun / Scaleway / Elastic Email**: 手数・無料枠・立地の
  いずれかで個人開発に合わない

## 決定(案)

**Mailjet** を第一候補、**Resend** を代替とする。

- Mailjet は無料枠が最大で、独自ドメインを持たない段階でも送信元アドレスの認証だけで動く
- Resend は設定が最軽量で、SMTP と API の両方を持つため、ホストが SMTP を塞いでいた
  場合の逃げ道がある
- どちらも SMTP で送れるため、`infra/smtp.go` をそのまま使える。実装変更が不要

検証では次の 4 社を測る。**4 つとも本番で使えることを条件に選んだ。**

| # | 候補 | 代表する軸 |
|---|---|---|
| 1 | Resend | 開発者向けの新興サービス。設定の軽さ |
| 2 | Mailjet | 無料枠の最大値。EU 系の大手 |
| 3 | SMTP2GO | SMTP 専業。到達率重視 |
| 4 | MailerSend | メール配信会社の transactional 部門 |

**検証から外したもの**

- **Gmail SMTP**: アプリからの自動送信が規約上グレーで、本番の選択肢にならない。
  「設定が最短の下限」として当初は候補にしていたが、採用しえないものを測る意味がない
- **SendGrid**: 新規の無料アカウントが審査で止まる事例が多く、登録できるかが不確実
- **Brevo**: 条件は悪くないが、上位 4 社に対して代表する軸がない

**API が Cloud Run の場合はこの決定が成立しない。** SMTP が塞がれているため、
API 送信の実装が必須になる。これは [ADR-0002](0002-backend-deploy-target.md) で
Cloud Run の順位を下げた理由の 1 つである。

## 結果・影響

- 設定するもの: `SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_SECURITY`、`MAIL_FROM`。
  コード変更は不要。認証情報は環境変数で渡し、リポジトリに書かない。
- **独自ドメインと SPF / DKIM の設定が要る。** 共有ドメインのままだと迷惑メール判定されやすい。
  フロントのドメイン(ADR-0001)を決めたあとに設定する。
- **ホストごとに SMTP の疎通確認が要る。** 机上では分からないため、Phase 4 で実測する。
- `mail_deliveries` は行が溜まる。削除ジョブを [ADR-0005](0005-async-job-platform.md) の
  `cleanup-expired` に含める。
- 送信失敗時の扱いは実装済み(`temporary` / `permanent` の区別と再試行)。本 ADR では変更しない。
