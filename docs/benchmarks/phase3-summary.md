# Phase 3: メール送信 4 候補のまとめ

- 計測日: 2026-09-21 〜 2026-09-22
- 方法: 本番イメージを各社の SMTP に向けてローカルで起動し、サインアップを実行。
  `mail_deliveries` テーブルを追って結果を確認(`scripts/bench/mail-verify.sh`)
- 各社の詳細は `phase3-<社名>.md`、候補の解説は `phase3-candidates.md`

## 結果

計測は 2 段階に分かれた。**最初は独自ドメインなし、次にドメインを取得して認証したあと**である。
この差がそのまま比較の核心になった。

### 第 1 段階: 独自ドメインなし

| 候補 | 送信 | 失敗の理由 |
|---|---|---|
| **Mailjet** | **成功** | — |
| Brevo | 失敗 | `525 Unauthorized IP address` |
| Resend | 失敗 | `550 You can only send testing emails to your own email address` |
| MailerSend | 失敗 | `450 The from.email domain must be verified` |

**ドメインを持たない状態で送れたのは Mailjet だけだった。**

### 第 2 段階: ドメインを取得して認証

サブドメインを 1 つ用意し、各社の指示に従って DNS レコードを登録した。

| 候補 | 送信 | 送信までの時間 | 解決に要した作業 | 受信箱に到達 |
|---|---|---|---|---|
| **Brevo** | **成功** | **2 秒** | 送信元 IP の許可登録 | ○ |
| **Mailjet** | **成功** | 4 秒 | **なし** | ○ |
| **Resend** | **成功** | 4 秒 | DKIM の登録 | ○ |
| **MailerSend** | **成功** | 6 秒 | SPF と DKIM の登録 | ○ |

**4 社すべてが送信でき、4 社すべて受信箱に届いた**(迷惑メール振り分けなし)。

## 事業者ごとの関門

送信に到達するまでに越える関門が 4 種類あった。**いずれも無料枠の通数とは無関係**である。

### Mailjet: 関門なし

送信元アドレスを 1 つ認証するだけで、任意の宛先に送れた。ドメインを取得したあと、
**Mailjet 側で未認証のドメインのアドレスに差し替えても送信できた**。

送信元の検証が 4 社で最も緩い。手軽さの裏返しとして受信側の信頼性が下がる懸念が
あったが、**実際には迷惑メールに振り分けられなかった**。

### Resend: DKIM の登録

共有ドメイン `onboarding@resend.dev` は登録アカウントのアドレス宛にしか送れない。
**`+` エイリアスすら「自分のアドレス」とみなされない**ほど厳密だった。

独自ドメインに DKIM を登録したところ解消した。SPF は未登録のままでも送信できたので、
**DKIM が通れば送信は許可される**設計と見られる。

### MailerSend: ドメイン認証(SPF + DKIM)

送信元が認証済みドメインでないと `450` で拒否される。SPF と DKIM の両方を登録して解消した。
**4 社で最も要求が厳しい。**

分類が `temporary` になる点に注意が要る。恒久的な設定不備に対して事業者が 450
(一時的なエラー)を返すため、アプリは再試行を続ける。アプリ側は SMTP の仕様どおりで、
問題は事業者の応答コードにある。

### Brevo: 送信元 IP の許可(ドメインでは解決しない)

**これが最も重い制約だった。** Brevo は SMTP リレーを使う IP アドレスを事前に登録させる。
ドメイン認証(SPF に `brevo-code` を登録)を済ませても `525 Unauthorized IP address` が
残り、Authorized IPs に接続元の IP を追加してはじめて送信できた。

ドメイン認証は一度で済むが、**IP の許可は接続元が変わるたびに必要になる**。
家庭用回線の IP は再接続で変わり、デプロイ先のインスタンスの IP も固定されない。

**Render や Cloud Run のように IP が固定されない基盤とは相性が悪い。**
Phase 4 でこの問題が再発するかを確かめる価値がある。

## 分かったこと

### 1. 通数は選定の基準にならない

このアプリが送るのはサインアップ確認と既登録通知の 2 種だけで、1 日に数通である。
無料枠は 300 通/日(Brevo)から 6,000 通/月(Mailjet)まで幅があるが、**どれも余る**。

**実際に効いたのは、登録できるかと、送信に到達するまでの関門だけだった。**

### 2. ドメインを取れば 4 社とも動くが、関門の種類が違う

| 候補 | ドメインなし | ドメイン認証で解決 | それ以外の関門 |
|---|---|---|---|
| Mailjet | **送れる** | 不要 | なし |
| Resend | 自分宛のみ | ○ DKIM | なし |
| MailerSend | 送れない | ○ SPF + DKIM | なし |
| Brevo | 送れない | **✕ 解決しない** | **送信元 IP の許可** |

事前の想定では「Mailjet と Brevo はドメイン不要」と括っていたが、
**Brevo には IP という別の関門があった。** 料金表や機能比較の表からは読み取れない。

**ドメイン認証は一度で済む作業だが、IP の許可は接続元が変わるたびに必要になる。**
この違いが運用コストの差として効く。

### 3. 設定の緩さと到達率は連動しなかった

Mailjet は未認証のドメインのアドレスからでも送信でき、**送信元の検証が最も緩い**。
受信側から見た信頼性が下がると予想したが、**4 社とも受信箱に届き、迷惑メールに
振り分けられたものはなかった**。

ただしこれは受信側が Gmail 1 つ、送信が各社 1 通ずつの結果である。
**継続的に送ったときの評判(レピュテーション)は別の話**で、本検証では測れない。

### 4. 失敗の分類は事業者の応答コードに依存する

アプリは SMTP の応答コードで `temporary` と `permanent` を分ける。

| 事業者 | コード | 分類 | 妥当性 |
|---|---|---|---|
| Brevo | `525` | `permanent` | ○ 正しい |
| Resend | `550` | `permanent` | ○ 正しい |
| MailerSend | `450` | `temporary` | **✕ 実際は設定不備で恒久的** |

MailerSend は恒久的な設定不備に 450 を返すため、アプリは上限まで無駄な再試行を続ける。
**アプリ側は仕様どおりで、問題は事業者の応答にある。**

### 5. 到達できないポートの挙動(Phase 4 の下準備)

4 社すべてで、閉じたポート(47777)に向けた送信は `failed` / `temporary` になった。
エラーは `dial tcp ...: i/o timeout` である。

**Cloud Run が SMTP を塞いでいる場合、これと同じ形で現れる。** Phase 4 で
この文字列が出たら、ポート遮断と判断してよい。

## ハマった点(検証ツール側の不具合)

測り直しが必要だった。いずれも**アプリではなく計測スクリプトの誤り**である。

### 1. 直前の社の結果を読んでいた

`mail_deliveries` から最新 1 行を無条件に読んでいたため、新しい行が作られる前に
ポーリングすると前の社の結果を拾った。実行前の時刻を基準に取り、それより新しい行だけを
見るよう修正した。

### 2. 遮断テストのポートが不適切だった

閉じている想定でポート 2525 を使っていたが、**Mailjet は 2525 を正規に受け付ける**。
遮断の模擬になっていなかった。確実に閉じている 47777 に変更した。

### 3. 同じ宛先では 2 回目以降が送られない

アプリの冪等キーは確認待ちの受付 ID から作られるため、同じアドレスで繰り返すと
送信も記録も発生しない。**アプリは正しく動いている。**

宛先を実行ごとに `+` エイリアスで一意にするよう修正した。
ただしこれが Resend の「自分宛のみ」制約に抵触し、結果として Resend の制約の
厳密さが判明した。

## ADR への反映

[ADR-0006](../adr/0006-email-delivery.md) の決定(Mailjet を第一候補)は
**実測で支持された。** ただし理由は当初の想定と違う。

| | 当初の理由 | 実測で判明した理由 |
|---|---|---|
| Mailjet を選ぶ根拠 | 無料枠が最大(6,000 通/月) | **通数は関係ない。関門が 1 つもない** |
| Brevo の位置づけ | ドメインなしで完結する代替 | **IP の許可が要る。IP が変わる基盤と相性が悪い** |
| Resend の制約 | 共有ドメインは自分宛のみ | **+ エイリアスも拒否**。DKIM だけで解消する |
| MailerSend の制約 | 本番は独自ドメインが必要 | そのとおり。SPF と DKIM の両方が要る |

**ドメインを取得した後は、Brevo 以外の 3 社に実質的な差がない。** 送信は 4〜6 秒でそろい、
到達率にも差が出なかった。選定は「関門の少なさ」で決まり、その基準では Mailjet が最良である。

## 未確認

- **送信時間の統計**: 2〜6 秒という値は各社 1 回の計測である。ばらつきを見るには繰り返しが要る
- **継続的なレピュテーション**: 1 通ずつの到達は確認したが、継続して送ったときの
  評判は本検証では測れない
- **Brevo の IP 制限がデプロイ先で再発するか**: Phase 4 で Render や Cloud Run に
  載せたとき、インスタンスの IP が変わって再び `525` が出ると予想される
