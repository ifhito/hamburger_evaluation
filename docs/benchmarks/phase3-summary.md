# Phase 3: メール送信 4 候補のまとめ

- 計測日: 2026-09-21
- 方法: 本番イメージを各社の SMTP に向けてローカルで起動し、サインアップを実行。
  `mail_deliveries` テーブルを追って結果を確認(`scripts/bench/mail-verify.sh`)
- 各社の詳細は `phase3-<社名>.md`

## 結果

| 候補 | 登録 | 送信 | 送信までの時間 | 失敗の理由 |
|---|---|---|---|---|
| **Mailjet** | ○ フリーメールで可 | **成功** | 5 秒 | — |
| Brevo | △ 企業名が要る | **失敗** | 2 秒 | `525 5.7.1 Unauthorized IP address` |
| Resend | ○ | **失敗** | 3 秒 | `550 You can only send testing emails to your own email address` |
| MailerSend | ○ | **失敗** | 4 秒 | `450 The from.email domain must be verified in your account` |

**ドメインを持たない状態で実際にメールを送れたのは Mailjet だけだった。**

## 失敗の内訳

3 社の失敗は**性質が違う**。いずれも無料枠の通数とは無関係である。

### Brevo: 送信元 IP の許可が要る(`525 Unauthorized IP address`)

Brevo は SMTP リレーを使う IP アドレスを事前に登録させる。自宅の回線から送ると
未登録の IP として拒否される。ダッシュボードで IP を許可リストに入れるか、
制限を解除する設定が要る。

**分類は `permanent`。** アプリは「再試行しても直らない」と判定しており、この判断は正しい。

デプロイ先を決めるうえでは重い制約になる。**サーバーの IP が変わるたびに登録し直す
必要がある**ためで、Render や Cloud Run のようにインスタンスの IP が固定されない
基盤とは相性が悪い。

### Resend: 共有ドメインは自分宛にしか送れない(`550`)

`onboarding@resend.dev` からの送信は、登録したアカウントのアドレス宛に限られる。
今回は宛先を `+` エイリアスで一意にしたため、**エイリアスは「自分のアドレス」と
みなされなかった**。

**分類は `permanent`。** 正しい判定である。

独自ドメインを認証すれば解消する。**事前に分かっていた制約が、実測で厳密に確認された**形。

### MailerSend: 送信元ドメインの認証が要る(`450`)

送信元に Gmail のアドレスを設定していたため、認証済みドメインでないとして拒否された。
試用ドメイン(`trial-xxxxx.mlsender.net`)のアドレスに変えれば通る見込み。

**分類は `temporary`。** 実際には設定を直さない限り直らないので、この判定は誤りに近い。
SMTP の応答コードが 450(一時的なエラー)であるため、アプリは仕様どおりに分類している。
**事業者側が恒久的な設定不備に 450 を返している**のが原因である。

## 分かったこと

### 1. 通数は選定の基準にならない

このアプリが送るのはサインアップ確認と既登録通知の 2 種だけで、1 日に数通である。
無料枠は 300 通/日(Brevo)から 6,000 通/月(Mailjet)まで幅があるが、**どれも余る**。

**実際に効いたのは、登録の可否と、ドメインなしで送れるかだけだった。**

### 2. 「ドメインなしで送れるか」の実態は 3 段階ある

| 段階 | 候補 | 内容 |
|---|---|---|
| そのまま送れる | **Mailjet** | 送信元アドレス 1 つの認証で、任意の宛先に送れる |
| 自分宛だけ送れる | Resend | 共有ドメインは登録アドレス宛のみ。**+ エイリアスも不可** |
| 送信元に制約がある | MailerSend | 認証済みドメインからしか送れない |
| 別の制約がある | Brevo | ドメインは不要だが、**送信元 IP の登録**が要る |

事前の想定では「Mailjet と Brevo はドメイン不要」と括っていたが、
**Brevo には IP という別の関門があった。** 表を見ただけでは分からない差である。

### 3. 失敗の分類は事業者の応答コードに依存する

アプリは SMTP の応答コードで `temporary` と `permanent` を分ける。

- Brevo の `525` → `permanent`(正しい)
- Resend の `550` → `permanent`(正しい)
- MailerSend の `450` → `temporary`(**実際は設定不備で恒久的**)

MailerSend は恒久的な設定不備に 450 を返すため、アプリは再試行を続けることになる。
`STATS_WORKER_MAX_ATTEMPTS` に相当する上限まで無駄な再試行が走る。
**アプリ側の分類は仕様どおりで、問題は事業者の応答にある。**

### 4. 到達できないポートの挙動(Phase 4 の下準備)

4 社すべてで、閉じたポート(47777)に向けた送信は `failed` / `temporary` になった。
エラーは `dial tcp ...: i/o timeout` である。

**Cloud Run が SMTP を塞いでいる場合、これと同じ形で現れる。** Phase 4 で
この文字列が出たら、ポート遮断と判断してよい。

## ハマった点(検証ツール側の不具合)

測り直しが 2 回必要だった。いずれも**アプリではなく計測スクリプトの誤り**である。

### 1. 直前の社の結果を読んでいた

`mail_deliveries` から最新 1 行を無条件に読んでいたため、新しい行が作られる前に
ポーリングすると前の社の結果を拾った。Brevo の「0 秒で成功」は Mailjet の行だった。

実行前の時刻を基準に取り、それより新しい行だけを見るよう修正した。

### 2. 遮断テストのポートが不適切だった

閉じている想定でポート 2525 を使っていたが、**Mailjet は 2525 を正規に受け付ける**。
遮断の模擬になっていなかった。確実に閉じている 47777 に変更した。

### 3. 同じ宛先では 2 回目以降が送られない

アプリの冪等キーは確認待ちの受付 ID から作られるため、同じアドレスで繰り返すと
送信も記録も発生しない。**アプリは正しく動いている。**

宛先を実行ごとに `+` エイリアスで一意にするよう修正した。
ただしこれが Resend の「自分宛のみ」制約に抵触し、結果として Resend の制約の
厳密さが判明した。

## ADR への反映

[ADR-0006](../adr/0006-email-delivery.md) の決定(Mailjet を第一候補)は
**実測で強く支持された。** ドメインを持たない状態で実際に送れたのは Mailjet だけである。

ただし理由は当初の想定と一部違う。

| | 当初の理由 | 実測で判明した理由 |
|---|---|---|
| Mailjet を選ぶ根拠 | 無料枠が最大(6,000 通/月) | **通数は関係ない。制約が最も少ない** |
| Brevo の位置づけ | ドメインなしで完結する代替 | **送信元 IP の登録が要る。動的 IP の基盤と相性が悪い** |
| Resend の制約 | 共有ドメインは自分宛のみ | **+ エイリアスも拒否される**ほど厳密 |

## 未確認

- **受信箱への到達**: Mailjet の送信は成功したが、受信箱に届いたか・迷惑メールに
  入ったかは目視の確認が要る
- **独自ドメインを認証した場合**: Resend と MailerSend は解消する見込み。
  ドメインを取得したら再計測する価値がある
- **Brevo の IP 制限**: ダッシュボードで許可すれば送れる可能性がある。
  デプロイ先の IP が変わる問題は残る
